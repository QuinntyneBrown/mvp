Manifest schema

A manifest is data, never code — no type resolution, no expressions, no includes. Only mvp new dotnet-angular-jwt-mvp reads one, through --config.

Shape at a glance

mvp.yaml
name: Acme                # required — everything else is optional
output: ./generated       # optional default output directory

entities:
  - name: Project
    properties:
      - name: Title
        type: string

pages:
  - name: Projects
    route: projects
    requiresAuth: true

components:
  - name: ProjectCard
    library: domain

Top level

FieldTypeRequiredDefaultNotes
name string yes — PascalCase, no spaces. Becomes the solution name, the namespace root, the kebab-cased Angular workspace prefix, and the directory created under the output path. --name overrides it.
output string no current directory Default output directory, resolved relative to where you run the command. --output overrides it.
entities list no empty Each entity produces a domain class, create and get-by-id handlers, a validator, a DTO, and an API controller.
pages list no empty Pages in addition to the always-generated sign-in, sign-up, and dashboard.
components list no empty Standalone Angular components created in the library you choose, with a public export.

entities[]

FieldTypeRequiredDefaultNotes
namestring yes— PascalCase and singular. Becomes the class name and a namespace segment.
propertieslist noempty Properties beyond the implicit Id and CreatedAt.

entities[].properties[]

FieldTypeRequiredDefaultNotes
namestring yes— PascalCase. Becomes the C# property name and its camelCase JSON and TypeScript name.
typestring nostring One of the supported types below. Any other spelling — including String or datetime — is rejected.

Supported property types

string · int · long · decimal · bool · DateTime · Guid

Two properties are always added for you

Every entity gets Id (Guid) and CreatedAt (DateTime). Declaring either one yourself is an error, not a duplicate.

pages[]

FieldTypeRequiredDefaultNotes
namestring yes— PascalCase. Becomes the standalone component class name and the page folder name once kebab-cased.
routestring no kebab-cased name Lower-case kebab segments, optionally separated by /.
requiresAuthboolean no true When true, the route is wrapped by the generated auth guard. Pages are protected unless you say otherwise.

Each page produces three files:

per page
frontend/projects/<name-kebab>-app/src/app/pages/<page-kebab>/<page-kebab>.page.ts
frontend/projects/<name-kebab>-app/src/app/pages/<page-kebab>/<page-kebab>.page.html
frontend/e2e/pages/<page-kebab>.page.ts

…plus a lazily loaded entry in app.routes.ts.

components[]

FieldTypeRequiredDefaultNotes
namestring yes— PascalCase.
librarystring no components api, components, or domain. Matched case-insensitively.
LibraryUse it for
componentsPure presentational UI with no domain knowledge.
domainComponents that depend on the api library and your models.
apiRarely — this library exists for typed HTTP clients and models.

Each component produces a .ts, .html, and .scss file under frontend/projects/<library>/src/lib/<component-kebab>/.

Validation rules

Everything below is checked before a single directory is created, and every problem is reported at once rather than one per run.

Identifier format

Solution, entity, property, page, and component names must all match:

PascalCase
^[A-Z][A-Za-z0-9]*$

ASCII letters and digits only, starting with an uppercase letter. No underscores, no hyphens, no spaces, no accented characters. Values are trimmed before checking.

Route format

kebab-case path
^[a-z0-9]+(?:-[a-z0-9]+)*(?:/[a-z0-9]+(?:-[a-z0-9]+)*)*$

So projects, order-history, and admin/audit-log are all valid; Projects, order_history, and /projects are not.

Reserved names

Applies toReserved valuesWhy
Any identifier CON PRN AUX NUL COM1–COM9 LPT1–LPT9 System Microsoft Reserved device names and namespace roots. Matched case-insensitively.
Entity names User RefreshToken Already generated by the authentication model.
Property names Id CreatedAt Generated automatically on every entity.
Page names SignIn SignUp Dashboard Baseline authentication pages.
Page routes sign-in sign-up dashboard Baseline authentication routes.
Task is fine as an entity name

The handler templates fully qualify System.Threading.Tasks.Task, so there is no shadowing. Other framework type names may still cause build errors in the generated code — if a generated project won’t compile, an entity name colliding with a System type is the first thing to check.

Duplicates

Detected case-insensitively across entities, pages, page routes, components, and the properties within each entity. Title and title on the same entity is a duplicate.

Size and unknown fields

  • A manifest larger than 1 MiB is rejected outright.
  • Unknown fields are ignored with a warning, not an error, so a manifest written for a newer version still runs.
  • An empty file, or one that parses to nothing, is an error.
unknown fields — exit code 0
Generating dotnet-angular-jwt-mvp...
warning: Unknown manifest field 'database' was ignored.
warning: Unknown property field 'nullable' was ignored.
Generated 85 files at '/work/out/Warned'.

Naming transforms

You write PascalCase; the generator derives everything else. OrderHistory becomes:

FormValueUsed for
PascalCaseOrderHistoryC# class names, Angular component class names
kebab-caseorder-historyFolders, file names, default routes, selectors
camelCaseorderHistoryJSON payloads, TypeScript members

Acronyms are handled: APIKeyList becomes api-key-list, not a-p-i-key-list.

Worked example

A fuller manifest with comments. Strip the comments before real use — they are here to explain, not to be kept.

example-manifest.yaml
# Solution name. PascalCase, no spaces. Becomes the .sln name, the namespace root,
# the Angular workspace prefix (kebab-cased), and the directory created under --output.
name: Acme

# Optional default output directory. Overridden by --output on the command line.
# output: ./generated

entities:
  - name: Project
    # Each property must use a C# type the templates understand:
    #   string, int, long, decimal, bool, DateTime, Guid
    # Id (Guid) and CreatedAt (DateTime) are added automatically — don't list them here.
    properties:
      - { name: Title,        type: string }
      - { name: Description,  type: string }
      - { name: BudgetCents,  type: long }
      - { name: StartsOn,     type: DateTime }
      - { name: IsActive,     type: bool }

  - name: TaskItem
    # Avoid naming an entity `User` or `RefreshToken` — those are reserved by the
    # built-in identity entities. `Task` works (templates handle the collision
    # with System.Threading.Tasks.Task) but `TaskItem` reads better.
    properties:
      - { name: Title,       type: string }
      - { name: IsComplete,  type: bool }
      - { name: DueOn,       type: DateTime }

pages:
  # The CLI always emits sign-in / sign-up / dashboard pages. List additional
  # pages here. Each gets a folder under projects/<name>-app/src/app/pages/,
  # a route in app.routes.ts, and a matching Playwright page object under e2e/pages/.
  - { name: Projects, route: projects, requiresAuth: true }
  - { name: Backlog,  route: backlog,  requiresAuth: true }
  - { name: About,    route: about,    requiresAuth: false }

components:
  # Optional. Empty stubs created in the chosen library. Use `domain` when the
  # component will depend on the api library, `components` when it's pure UI.
  - { name: ProjectCard,  library: domain }
  - { name: EmptyState,   library: components }

That manifest generates 77 + 8·2 + 3·3 + 3·2 = 108 files. The arithmetic is explained on Generated output.
