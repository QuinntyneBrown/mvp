Library API

QuinntyneBrown.Mvp.Core is the engine the CLI is built on, published as an ordinary NuGet package. Use it when generation should be a feature of your own application rather than a terminal command.

This one is published

Unlike the CLI, the engine library is on NuGet.org. Templates ship inside the package, so generation still needs no network access.

Install

shell
dotnet add package QuinntyneBrown.Mvp.Core

Register the engine

AddMvpCore() registers everything as singletons — the loader, the validator, both generators, the transactional output writer, and the process runner.

C#
using Microsoft.Extensions.DependencyInjection;
using Mvp.Core;

var services = new ServiceCollection()
    .AddMvpCore()
    .BuildServiceProvider();
ServiceImplementationRole
IManifestLoaderYamlManifestLoaderReads and deserializes a YAML manifest.
ManifestValidator—Validates in aggregate and produces an immutable model.
IFullStackGeneratorFullStackGeneratorGenerates the complete authenticated solution.
IIncrementalGeneratorIncrementalGeneratorGenerates a single solution part.
ITransactionalGenerationOutputTransactionalGenerationOutputStaging, publication, backup, and rollback.
IProcessRunnerProcessRunnerCancellable child processes, for the Angular CLI opt-in.

Generate a full-stack solution

C#
using Microsoft.Extensions.DependencyInjection;
using Mvp.Core;
using Mvp.Core.Features.FullStack.Generation;
using Mvp.Core.Features.FullStack.Manifest;

var services = new ServiceCollection().AddMvpCore().BuildServiceProvider();

var loaded = services.GetRequiredService<IManifestLoader>().Load("mvp-manifest.yaml");

var manifest = services.GetRequiredService<ManifestValidator>()
    .Validate(loaded.Manifest, nameOverride: null, outputOverride: "./out", loaded.Warnings);

var result = await services.GetRequiredService<IFullStackGenerator>()
    .GenerateAsync(manifest, force: false, CancellationToken.None);

Console.WriteLine($"{result.Artifacts.Count} files written to {result.TargetPath}");

The three steps are deliberately separate. Loading gives you the raw input and any unknown-field warnings; validating turns that into an immutable model or throws with the complete problem list; generating writes. You can inspect or reject between any two.

Generating without a file

When there is no manifest, use an empty load result and let nameOverride supply the name — the same path the CLI takes for --name Contoso with no --config:

C#
var loaded = ManifestLoadResult.CreateEmpty();

var manifest = services.GetRequiredService<ManifestValidator>()
    .Validate(loaded.Manifest, nameOverride: "Contoso", outputOverride: "./out", loaded.Warnings);

Generate a single project

C#
using Mvp.Core.Features.Generation;

var result = await services.GetRequiredService<IIncrementalGenerator>().GenerateAsync(
    new GenerationRequest(GenerationKind.Api, "Acme", "./out"),
    CancellationToken.None);

Exceptions

Map these to your own error surface. The CLI’s exit codes are shown for reference — see Errors & exit codes.

ExceptionThrown whenCLI exit
ManifestValidationException Validation failed. The Errors property carries the complete list. 1
GenerationConflictException The target exists and force is false. 2
GenerationException Template, filesystem, or publication failure. 3
ExternalToolException Subclass of GenerationException; the Angular CLI could not start or failed. 3
OperationCanceledException The cancellation token was signalled. 130

They live in Mvp.Core.Errors. Reading Errors off a ManifestValidationException is how you surface every problem at once instead of one per attempt.

C#
try
{
    var manifest = validator.Validate(loaded.Manifest, null, "./out", loaded.Warnings);
    return await generator.GenerateAsync(manifest, force: false, cancellationToken);
}
catch (ManifestValidationException exception)
{
    foreach (var error in exception.Errors)
    {
        logger.LogWarning("Manifest problem: {Error}", error);
    }

    throw;
}

Behaviour you inherit

  • Validation precedes every write. No directory is created for input that will not validate.
  • Generation is transactional. Rendering happens in a staging directory and publishes atomically, so a failed or cancelled run cannot look like a complete one.
  • Existing output is a conflict, not a target. Replacement keeps a sibling backup and rolls back on failure.
  • Cancellation is honoured end to end, including terminating any child process tree.
  • Templates are embedded. No network access, no template directory to ship alongside your application — and no way to override them.
Consumer text is untrusted input

If your application accepts a manifest from a user, run it through ManifestValidator before it reaches anything else. Validation is what stops manifest values being used as paths or process arguments — it is not decoration you can skip for speed.
