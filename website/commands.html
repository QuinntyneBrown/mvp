Command reference

One command group, nine generators. Everything on this page is captured from mvp 2.1.0 — run mvp new <command> --help for the authoritative options on your installed build.

Command tree

structure
mvp
└── new
    ├── dotnet-angular-jwt-mvp   the full authenticated solution
    ├── solution                 .NET solution + API + core + infrastructure + Angular app
    ├── api                      .NET Web API project
    ├── core                     .NET core class library
    ├── infrastructure           .NET infrastructure class library
    ├── app                      Angular application
    ├── api-library              Angular API library
    ├── components-library       Angular components library
    └── domain-library           Angular domain library

Global options

OptionDefaultDescription
--diagnostic false Include stack traces and internal details in errors. Applies to every subcommand. This is the only way to see internal exception detail — without it, messages never expose stack traces or machine-local paths.
--version — Print the version and source revision, e.g. 2.1.0+36ae856….
-?, -h, --help — Show help for the root command or any subcommand.

Shared generation options

Every new subcommand accepts these three:

OptionDefaultDescription
-n, --name — PascalCase solution or project name. Required on the eight incremental commands; optional on dotnet-angular-jwt-mvp, where it may come from the manifest instead.
-o, --output current directory Output directory. Missing parent directories are created — after validation, never before.
-f, --force false Replace an existing target using a recoverable backup and atomic move. Without it, an existing target is a conflict and exits 2.

How the name is resolved

For dotnet-angular-jwt-mvp, --name wins over the manifest’s name: field. If neither is supplied, validation fails with exit code 1 before anything is written.

How the output directory is resolved

  1. --output, if supplied.
  2. Otherwise the manifest’s output: field (full-stack command only).
  3. Otherwise the current working directory.

The final target is always <resolved output>/<target directory>, where the target directory name is listed per command below.

mvp new dotnet-angular-jwt-mvp

The primary generator. Produces the complete JWT-authenticated .NET 10 and Angular 22 solution from options, from a YAML manifest, or from both.

OptionRequiredDescription
-n, --nameoptionalPascalCase solution name. Overrides the manifest.
-o, --outputoptionalOutput directory.
-c, --configoptionalYAML manifest describing entities, pages, and components.
-f, --forceoptionalReplace an existing target.

Target directory: <output>/<Name>. File count: 77 + 8·entities + 3·pages + 3·components.

From a manifest

shell
mvp new dotnet-angular-jwt-mvp --config samples/sample-mvp.yaml --output ./out
exit code 0
Generating dotnet-angular-jwt-mvp...
Generated 102 files at '/work/out/Acme'.

From a name alone

shell
mvp new dotnet-angular-jwt-mvp --name Contoso --output ./out
exit code 0
Generating dotnet-angular-jwt-mvp...
Generated 77 files at '/work/out/Contoso'.

You still get the full authenticated baseline — registration, sign-in, the guard, the interceptor, the Angular libraries, and the Playwright suite. What you don’t get is any domain of your own.

Replacing an existing target

shell
mvp new dotnet-angular-jwt-mvp --config samples/sample-mvp.yaml --output ./out --force
exit code 0
Generating dotnet-angular-jwt-mvp...
Generated 102 files at '/work/out/Acme'.
Replaced the existing target '/work/out/Acme' using transactional backup and rollback.
--force replaces the whole tree

It is safe in the sense that a failed publication rolls back — not in the sense that your edits survive. Anything you changed inside the target is gone. Generate somewhere else and merge.

Manifest warnings

Unknown fields do not fail the run. They are reported on stderr and ignored, so a manifest written for a newer version still works:

exit code 0
Generating dotnet-angular-jwt-mvp...
warning: Unknown manifest field 'database' was ignored.
warning: Unknown property field 'nullable' was ignored.
Generated 85 files at '/work/out/Warned'.

Incremental commands

Eight focused generators for when you want one project rather than a solution. All of them require --name, and none of them read a manifest.

CommandTarget directoryFilesProduces
solution<Name>/15A .NET solution, API, core, infrastructure, and Angular app.
api<Name>.Api/2A .NET Web API project.
core<Name>.Core/2A .NET core class library.
infrastructure<Name>.Infrastructure/2A .NET infrastructure class library.
app<Name>.App/8An Angular application.
api-library<Name>.Api/4An Angular API library.
components-library<Name>.Components/4An Angular components library.
domain-library<Name>.Domain/4An Angular domain library.
api and api-library collide

Both target <Name>.Api/. Running one after the other in the same output directory produces a conflict and exit code 2, not a merge. Use different names or different output directories.

The --use-angular-cli opt-in

This is the only code path in the whole tool that starts an external process. It runs your locally installed ng with exactly these arguments, passed as a list rather than a concatenated string:

child process
ng new <name-kebab>-app --directory . --routing --style scss --standalone --skip-git --skip-install --defaults

The result is still staged and published transactionally. If ng is missing or fails, you get exit code 3 — see external tool failures.

Prefer the default

Without this flag, generation is offline, deterministic, and version-stable. With it, you inherit whatever your machine’s Angular CLI produces.

mvp new api-library, components-library, domain-library

shell
mvp new api-library --name OrderDesk --output ./out
exit code 0
Generating api-library...
Generated 4 files at '/work/out/OrderDesk.Api'.

Each library produces the same four files, named for its role:

CommandDirectoryService file
api-libraryOrderDesk.Api/src/lib/api.service.ts
components-libraryOrderDesk.Components/src/lib/components.service.ts
domain-libraryOrderDesk.Domain/src/lib/domain.service.ts

Plus package.json, README.md, and src/lib/public-api.ts in every case.

Output conventions

Success output is the same shape for every command:

stdout
Generating <command>...
Generated <n> files at '<absolute target path>'.
LineStreamWhen
Generating <command>...stdoutAlways, at the start.
warning: <text> (manifest)stderrUnknown manifest fields, before generation.
Generated <n> files at '<path>'.stdoutOn success.
Replaced the existing target …stdoutOnly when --force replaced something.
warning: <text> (result)stdoutPost-generation warnings, such as a failed backup cleanup.

Because warnings and errors go to stderr while results go to stdout, you can pipe generation output without swallowing diagnostics.

Exit codes at a glance

CodeMeaning
0Success.
1Invalid syntax, manifest, or input.
2Output conflict — the target exists and --force was not given.
3Generator or external-tool failure.
70Unexpected internal failure.
130Cancelled.
