Errors & exit codes

Exit codes are stable and safe to script against. Every message below is emitted verbatim by mvp 2.1.0, with <…> marking the parts filled in at runtime.

Exit codes

CodeNameRaised when
0Success Generation completed. Warnings may still have been printed.
1InvalidInput Manifest validation failed, the manifest file was missing or unreadable, access was denied, or the command line itself was invalid.
2Conflict The target directory already exists and --force was not supplied.
3GenerationFailure A template, filesystem, or external-tool failure during generation.
70InternalError An unexpected failure the tool has no specific handling for. Please report it.
130Cancelled The run was cancelled, typically with Ctrl+C.
Scripting

Exit code 2 means “already generated”, not “broken”. In an idempotent script, treat 0 and 2 as acceptable and everything else as a failure.

--diagnostic

By default no message exposes a stack trace or internal detail. Adding --diagnostic to any command replaces the message with the full exception text — including a stack trace — for the failure kinds that carry one.

shell
mvp new dotnet-angular-jwt-mvp --config mvp.yaml --output ./out --diagnostic

Include that output when reporting a bug. Leave the flag off in scripts and CI logs — it can surface machine-local paths.

Which stream goes where

OutputStream
Progress and success linesstdout
Manifest warnings (unknown fields)stderr
Post-generation warnings (for example, backup cleanup)stdout
All errorsstderr

Validation errors exit 1

Validation is aggregate: every problem is reported in one run, prefixed with Input validation failed: and one -  line each. Nothing is written to disk.

shape
Input validation failed:
- <first problem>
- <second problem>

<label> below is one of Solution name, Name, Entity <n> name, Property <n> on '<Entity>', Page <n> name, or Component <n> name. Positions are 1-based.

<label> is required. Supply --name or set 'name:' in the manifest.

Cause. No name was supplied on the command line or in the manifest.

Fix. Add --name Contoso, or set name: at the top of the manifest. --name wins when both are present.

<label> '<value>' must be a PascalCase identifier containing only ASCII letters and digits.

Cause. The value does not match ^[A-Z][A-Za-z0-9]*$ — it has spaces, punctuation, accented characters, or a lowercase first letter.

Fix. Rename it. order desk → OrderDesk; order_desk → OrderDesk.

<label> '<value>' is reserved and cannot be used.

Cause. The value is a reserved device name or namespace root: CON, PRN, AUX, NUL, COM1–COM9, LPT1–LPT9, System, or Microsoft. Matched case-insensitively.

Fix. Choose a different name.

Entity name '<Entity>' is reserved by the authentication model.

Cause. You declared an entity called User or RefreshToken; both are already generated.

Fix. Rename yours — Account, Member, Profile — or extend the generated User class after generating.

Property name '<Entity>.<Property>' is generated automatically and must not be declared.

Cause. You declared Id or CreatedAt. Every entity gets Id as a Guid and CreatedAt as a DateTime.

Fix. Remove the property.

Property '<Entity>.<Property>' has unsupported type '<type>'. Supported types: string, int, long, decimal, bool, DateTime, Guid.

Cause. The type is outside the supported set, or spelled differently — matching is exact, so String, datetime, and double all fail.

Fix. Use one of the seven listed types, matching case exactly. For money, decimal or an integer minor-unit field such as BudgetCents: long both work.

Page '<Page>' conflicts with a baseline authentication page or route.

Cause. The page name is SignIn, SignUp, or Dashboard, or its route is sign-in, sign-up, or dashboard. All three are always generated.

Fix. Drop the page from the manifest and edit the generated one, or pick a different name and route.

Page '<Page>' route '<route>' must contain only kebab-case path segments.

Cause. The route does not match ^[a-z0-9]+(?:-[a-z0-9]+)*(?:/[a-z0-9]+(?:-[a-z0-9]+)*)*$.

Fix. Lowercase it, replace underscores and spaces with hyphens, and drop any leading or trailing slash. Order_History → order-history.

Component '<Component>' has unsupported library '<library>'. Supported libraries: api, components, domain.

Cause. library is not one of the three workspace libraries.

Fix. Use components for pure UI, domain for components that know about your models, api for HTTP concerns. Omitting the field defaults to components.

Duplicate <label> value '<value>'.

Cause. Two entries collide. <label> is entities, pages, page routes, components, or properties on entity '<Entity>'. Comparison is case-insensitive, so Title and title collide.

Fix. Remove or rename one of them.

Output directory cannot be empty.

Cause. The resolved output path was blank.

Fix. Supply --output, or remove an empty output: from the manifest so the current directory is used.

Output path is invalid: <reason>

Cause. The output path could not be resolved — invalid characters, an unsupported form, or a path too long for the platform.

Fix. Use a shorter absolute path, or a simple relative one such as ./out.

Manifest loading errors exit 1

Manifest file '<path>' was not found.

Cause. --config points at a path that does not exist.

Fix. Check the path; it is resolved relative to your current directory, not to the output directory.

Manifest exceeds the 1024 KiB size limit.

Cause. The file is larger than 1 MiB.

Fix. A manifest this large almost certainly points at the wrong file. Split the work into several smaller solutions if it is genuine.

Manifest could not be read: <reason>

Cause. An I/O failure — the file is locked by another process, or on an unavailable volume.

Fix. Close whatever holds the file and retry.

Manifest is empty.
Manifest is empty or invalid.

Cause. The file is blank, whitespace only, or parses to nothing (for example, entirely comments).

Fix. At minimum, give it a name: line.

Manifest YAML is invalid: <reason>

Cause. The file is not well-formed YAML. Inconsistent indentation and tab characters are the usual culprits.

Fix. YAML requires spaces, never tabs. The reason text names the line and column.

Warnings exit 0

Warnings never stop a run.

Unknown <location> field '<key>' was ignored.

Cause. The manifest contains a field the schema does not define. <location> is manifest, entity, property, page, or component. Printed to stderr.

Fix. Usually a typo — route misspelled as path, or requiresAuth as requireAuth. Unknown fields are tolerated so a manifest written for a newer version still runs, which means a typo silently does nothing. Check the schema against the warning.

Generation succeeded, but backup cleanup failed: <reason>

Cause. A --force replacement published successfully, but the temporary backup directory could not be deleted.

Fix. Your generated tree is correct and complete. Delete the leftover .<Name>.mvp-backup-* directory beside the target by hand.

Conflicts exit 2

The target '<path>' already exists. Re-run with --force to replace it safely.

Cause. The target directory exists and --force was not given. This is a refusal, not a failure — nothing was touched.

Fix. Generate into a different --output, delete the existing directory yourself, or pass --force to replace it wholesale. See Output safety before choosing --force.

Generation failures exit 3

Generation could not be committed to '<path>'.

Cause. Rendering succeeded but publication failed — a permission problem, a lock held by an editor or antivirus scanner, or a full disk.

Fix. Close anything holding files in the target, check free space and permissions, then retry. If --force was in play, the previous tree has already been restored.

The target path must have a parent directory.

Cause. The resolved target is a filesystem root, so there is nowhere to place the staging directory.

Fix. Point --output at a real directory rather than a drive root.

Template output path '<path>' escapes the target directory.

Cause. A rendered path resolved outside the target root. Containment is enforced on every write.

Fix. Input validation should make this unreachable — please report it with --diagnostic output.

Packaged template resource '<name>' was not found.
The packaged full-stack template manifest was not found.
The packaged full-stack template manifest is missing or empty.
Invalid packaged template manifest entry: '<line>'.

Cause. The tool’s embedded templates are missing or malformed — a damaged or hand-modified installation.

Fix. Reinstall the tool. If a clean install still fails, report it.

External tool failures

Only reachable through mvp new app --use-angular-cli.

Angular CLI could not be started. Install Angular CLI or omit --use-angular-cli to use packaged templates.

Cause. ng (or ng.cmd on Windows) is not on your PATH.

Fix. Drop the flag — the packaged templates need no Angular CLI — or install it with npm install -g @angular/cli.

Angular CLI generation failed: <detail>

Cause. ng started but returned a non-zero exit code. <detail> is its stderr, or exit code <n> when it said nothing.

Fix. Read the detail. A version incompatibility between your Angular CLI and the expected arguments is the common cause; the packaged template path avoids the problem entirely.

Internal errors exit 70

An unexpected internal error occurred.

Cause. A failure with no specific handling. The message is deliberately terse so nothing internal leaks.

Fix. Re-run with --diagnostic for the full exception and open an issue with that output, your manifest, and the exact command line.

Cancellation exit 130

Generation cancelled.

Cause. You interrupted the run.

Effect. The staging directory is removed, the target is untouched, and any child process tree is killed. Nothing to clean up.

Common situations

SymptomWhat is happening
dotnet tool install -g Mvp.Cli cannot find the package A configured NuGet source is shadowing nuget.org, or you asked for a version that only exists as a prerelease. Add --prerelease, or pass --add-source https://api.nuget.org/v3/index.json — see Installation.
mvp is not recognised after installing The .NET tools directory is not on your PATH, or the shell predates the install. Open a new terminal.
Changes to the source have no effect You are running an installed copy. Re-pack and dotnet tool update, or use dotnet run --project src/Mvp.Cli --.
A manifest field seems to be ignored Look for an Unknown … field warning on stderr — the name is probably misspelled.
The generated backend does not compile Most often an entity name colliding with a framework type. Task is handled; others may not be. Rename and regenerate.
Generated data disappears on restart Expected. The default store is in-memory; set ConnectionStrings:Default to use SQL Server.
